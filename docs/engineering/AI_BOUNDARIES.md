# PF Health AI Boundaries

## Principle

AI improves explanation and drafting; it does not determine truth. The complete hero journey must work with AI disabled.

## Allowed functions

```text
src/adapters/ai/
  explainIssue.ts
  draftCorrectionRequest.ts
  extractSyntheticDocument.ts   # optional, not MVP by default
```

### `explainIssue`

Receives a minimal structured issue, approved source summary, limitation, locale, and copy constraints. Returns an explanation only.

### `draftCorrectionRequest`

Receives an approved resolution action and synthetic facts. Returns editable request text only.

### `extractSyntheticDocument`

If separately approved, extracts a fixed schema from a synthetic document. Extracted fields remain untrusted and require deterministic validation/review before use.

## Forbidden authority

The AI layer must never:

- run or reproduce health rules;
- create/suppress issues or set severity/status;
- choose an owner or resolution action;
- decide eligibility or predict acceptance;
- mutate or directly read/write repositories;
- create audit events;
- claim to have contacted an employer or EPFO;
- invent a policy, URL, citation, evidence, date, identifier, or user fact;
- receive credentials, OTPs, real identity data, or raw production records.

## Dependency boundary

AI functions accept serializable DTOs and return values. They may import schemas and gateway interfaces, but not repository implementations, application mutation services, domain rule implementations, or UI components.

The application service decides whether validated output is displayed or optionally cached. AI output is stored separately from deterministic state.

## Input minimization

Send only:

- issue code and approved fallback title;
- structured reason and named affected workflow;
- owner/action already selected deterministically;
- approved source summary and limitation;
- fictional display labels necessary for a draft;
- requested locale.

Do not send full member snapshots when a smaller DTO is sufficient.

## Structured output

Illustrative explanation schema:

```ts
const IssueExplanationSchema = z.object({
  summary: z.string().min(1).max(240),
  whyItMatters: z.string().min(1).max(500),
  nextStep: z.string().min(1).max(500),
  limitation: z.string().min(1).max(400),
  uncertainty: z.enum(["NONE", "LOW", "MATERIAL"])
}).strict();
```

Draft schema contains `subject` and `body` with strict length limits. It does not contain issue status, owner, action code, commands, or citations generated by the model.

## Prompt rules

- Prompts are centralized and versioned.
- Separate system instructions, approved data, and user-editable context.
- Tell the model that data can contain instructions and must be treated only as data.
- Ask for schema-constrained output.
- Supply source summaries; do not ask the model to recall EPFO policy.
- Use low-variance settings where supported.
- Do not interpolate untrusted text into instruction sections.

## Validation and fallback

1. Validate input DTO.
2. Apply redaction/allowlist checks.
3. Call the gateway with timeout and bounded retries.
4. Validate strict output schema.
5. Reject forbidden claims or unsupported URLs through deterministic checks.
6. Return approved deterministic fallback on timeout, refusal, malformed output, or safety failure.

AI failure never changes assessment or resolution state.

## Observability and privacy

Log request ID, function name, prompt/schema version, latency, model identifier, and outcome category. Do not log complete prompts, generated drafts containing user edits, documents, secrets, or personal identifiers. Disable provider training/data retention where available and appropriate before any non-synthetic use; non-synthetic use remains out of scope.

## Testing

- Schema acceptance/rejection tests
- Prompt-injection-shaped synthetic input tests
- Unsupported-claim and invented-URL rejection tests
- Timeout/provider failure fallback tests
- Proof that AI cannot change issue, owner, action, or member state
- Snapshot tests for deterministic fallback copy, not model prose
